# AV-TokenVault 模型选择说明

## 当前定位

AV-TokenVault 的核心目标不是直接做一个完整 RAG 应用，而是构建一个本地运行的音视频 token 化与向量入库底座。系统先完成这条链路：

```text
音视频上传 -> 抽帧/抽音轨 -> 切片 -> encoder/tokenizer -> SQLite 向量入库
```

当前默认仍使用 mock encoder，目的是保证 Mac 本机无需 GPU 或大模型下载也能稳定演示完整流程。新增的 transcript 与 search 能力让系统变成 RAG-ready：数据已经按时间戳组织、可检索、可供后续问答系统引用。

## 为什么先保留 mock encoder

- 验证系统架构，不被模型安装和显存问题阻塞。
- 保证测试稳定、速度快。
- 让后端 pipeline、SQLite 存储、前端展示先形成闭环。
- 后续替换真实模型时，只需要新增 encoder adapter，不重写主流程。

## 第一批真实模型建议

### Whisper

用途：把音频片段转成带时间戳的文字。

适合场景：

- 课堂视频
- 会议录音
- 访谈
- 汇报视频

优势：

- 输出文本，天然适合检索和问答。
- 中文和英文都能处理。
- 比直接存音频 embedding 更容易向导师解释价值。

### BGE-M3

用途：把 transcript 文本转成文本 embedding。

适合场景：

- 中文/英文混合检索
- 视频讲话内容检索
- 后续接 RAG 或问答系统

优势：

- 多语言能力好。
- 适合中文语义检索。
- 可以本地部署，符合本地原型定位。

本机部署备注：

- `BAAI/bge-small-zh-v1.5` 已验证能快速运行，输出 512 维向量，适合作为 Mac 默认演示模型。
- `BAAI/bge-m3` 已验证能运行，输出 1024 维向量，但首次下载和加载明显更慢，适合作为增强选项。

## 后续可选模型

### CLIP / SigLIP

用途：把视频帧和文本 query 放到同一个语义空间，用于文本搜画面。

例子：

- "找有图表的画面"
- "找出现实验设备的片段"
- "找有人在讲台前的画面"

本机已验证 OpenCLIP adapter：

- `open-clip:ViT-B-32:laion2b_s34b_b79k`
- 输出 512 维图像向量。

### CLAP

用途：处理非语音音频事件。

例子：

- 掌声
- 音乐
- 机器运行声
- 警报声

本机已验证 MS-CLAP adapter：

- `msclap:2023`
- 输出 1024 维音频向量。

### Qwen2.5-VL 等 VLM

用途：把关键帧转成文字描述或做 OCR/图表理解。

它更适合第二阶段，因为本地运行成本比 transcript 路线更高。

## 推荐汇报说法

可以这样介绍：

> 当前系统先实现了本地音视频处理闭环：支持上传视频和音频，视频会抽帧和抽音轨，音频会切片，然后分别通过 encoder 生成 embedding，并写入 SQLite。当前版本使用 mock encoder 验证流程，同时新增 transcript 和 text embedding 结构，让系统具备检索扩展能力。后续可以替换为真实模型，例如语音内容用 Whisper，文本向量用 BGE-M3，视频帧用 CLIP/SigLIP，非语音音频用 CLAP。

一句话定位：

> 这个系统不是直接做 RAG，而是做音视频多模态 token 化与向量入库底座，并为后续检索、问答和 RAG 应用预留接口。
